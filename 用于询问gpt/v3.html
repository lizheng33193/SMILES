你现在这串 NaN 是在模型输出阶段就出现了（所以训练第一轮的 loss 就是 nan，验证里我看到你“用均值替换 NaN”的兜底也报了 Mean of empty slice）。根因几乎可以确定：进 Transformer 编码器时整条序列被“全遮盖”了，导致注意力里 softmax(-inf, -inf, …) 直接变成 NaN，一路传到回归头和评估。 这个情况最常见的两个触发源：

  1. mask 极性或来源不对 → 把“非 PAD”当成了 PAD 去屏蔽；
  2. 样本被分词→索引后是“全 PAD”（例如 processed_smiles 为空、或全是 OOV 被映射到 <pad>），于是对这个样本来说 所有 key 都被 mask 掉。

下面给你“一步到位”的修复方案（在哪个函数改、改啥），以及两处快速自检。我对的是你发来的最新版脚本（smiles2proc.py）。

立刻修改（必须做）

① 在编码器里自己重算 PAD mask，不要再信任外部传进来的 src_mask

位置：ImprovedEncoder.encode_with_attention_pooling 目的：确保传给 TransformerEncoder 的 src_key_padding_mask 一定是「PAD→True、非 PAD→False」。

  • 你当前代码直接用调用方传入的 src_mask，假设它已经是 PAD 掩码：True=PAD。但很多数据管道里的“mask”定义恰好相反（True=有效 token）。一旦极性不符，就会把整条有效 token 都 mask 掉，第一层注意力就产生 NaN。

  • 改法：在函数里用 src 自己算：

    • pad_mask = (src_before_transpose == 0)（假设 <pad> 的索引是 0；和你的词表一致）；
    • src_key_padding_mask=pad_mask 传给每一层 encoder；
    • 后面的 valid_mask 也用这个 pad_mask 来算（valid_mask = (~pad_mask)）。

这一步从根上杜绝“极性搞错”的 NaN 源头。

② 加**“全 PAD 样本”保护**，避免 softmax(all -inf)

位置：同一函数 encode_with_attention_pooling，在构造 pad_mask 之后

  • 检测 all_pad = pad_mask.all(dim=1)（shape: (B,)）。

  • 如果某些样本 all_pad=True：

    • 至少解开一个位置（比如第 0 位）：pad_mask[all_pad, 0] = False；
    • 可选：把该位置的 token 设成 <sos> 或 <unk>（不设也行，padding_idx=0 的 embedding 常为 0，注意力仍然可计算）。

  • 继续用 pad_mask 作为 src_key_padding_mask 进各层 encoder。

这样即便数据里混入了“空序列”，也不会在注意力里炸 NaN。

③ 你的均值/最大池化已经避免了 /0，但要防止 max 的输入全被置成 -1e9

位置：encode_with_attention_pooling 末尾的池化部分

  • 你用 masked_fill(~valid_mask, -1e9) 再 max(dim=1)，如果一个样本全 PAD，max 会给出 -1e9（不是 NaN），这一步本身是安全的。
  • 真正的 NaN 来自注意力之前（上一条已修），所以这里不用再改。但为了数值更稳，可把 -1e9 换成 torch.finfo(output.dtype).min/2（可选）。

④ 数据侧硬过滤“空序列/全 PAD”样本

位置：prepare_data_with_log_transform（或你的 Dataset 初始化之前）

  • 先用和训练一致的分词器 验证每一行：

    • 若 processed_smiles 为空字符串、全空格、或分词后为长度 0，则直接丢弃该样本；
    • 统计一次“空序列/全 PAD 样本数量”，打印出来（>0 就说明你的数据确实存在这类脏样本）。

这样从源头减少异常样本进入训练/评估，和上面 ② 的“在线兜底”配合使用最稳。

加两处「一次性自检」日志（帮助你确认修干净了）

把这两段打印放到 encode_with_attention_pooling 开头（只在第一个 batch 打一次就好）：

  1. 极性自检（核对“外部 mask”和“由 src==0 计算的 PAD mask”是否一致）：

    • 计算 ext_mask（调用方传入的、转为 bool 的）；
    • 计算 pad_mask = (src_before_transpose==0)；
    • mismatch = (ext_mask ^ pad_mask).float().mean().item()
    • 打印 mismatch（大于 0.01 基本就是极性错了，直接忽略外部 mask 改用本地 pad_mask）。

  2. 全 PAD 比例：

    • all_pad_rate = pad_mask.all(dim=1).float().mean().item()；
    • 打印它（不应大于 0；若 >0，说明数据里确实有“空序列”，上面的 ②/④ 会兜住）。

不要继续“用均值替换 NaN”掩盖问题

你在 evaluate() 里看到的 Warning: NaN detected in predictions, replacing with mean 和 Mean of empty slice 说明整列全 NaN，这其实是上游 attention NaN 的症状。先把 ①②④ 做了，评估里就不应该再出现 NaN；建议保留日志检查，但不要用替换均值来“糊过去”。

顺带解答你日志里的两个 Warning

  • enable_nested_tensor ... batch_first：只是提示用 batch_first=True 会更快，对数值无影响。
  • verbose is deprecated：学习率调度器的小提示，不影响结果。

快速复现用的 Checklist

  • 在 encode_with_attention_pooling 内部重算 pad_mask=(src==0)，传给 src_key_padding_mask，并用它构造 valid_mask。
  • 全 PAD 保护：对 pad_mask.all(dim=1) 的样本，强制解开一个位置（如 index=0）。
  • prepare_data_with_log_transform 里剔除 processed_smiles 为空/分词后长度为 0 的样本，并打印统计。
  • 首个 batch 打印一次 mismatch（外部 mask vs (src==0)）、all_pad_rate，确认为 0。
  • 移除评估里“用均值替 NaN”的分支（或保留日志但不替换），确保训练第一轮开始就没有 NaN。
