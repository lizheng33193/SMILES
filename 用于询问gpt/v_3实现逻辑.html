下面只做“思路 & 改进”的对照总结（不再讨论效果问题）。我把你给的两份脚本逐段看过：原始版 run_downstream_fixed.py 和 改进版 smiles2proc_v3.py。按“数据→特征→模型→训练→评估/推理→工程细节”6 个环节，说明最初怎么做、后来改了什么、为什么这么改。

一、数据与预处理

项目 原始版 run_downstream_fixed.py 改进版 smiles2proc_v3.py 为什么这么改
输入列 直接读 processed_smiles + 标签三列 同样读 processed_smiles；显式传入 NoOpTransform（只做 .split()） 保证验证/测试阶段完全确定性，不触发任何随机 SMILES 增广；与已分好词的数据完美对齐
标签变换 三列统一用一个 StandardScaler 逐列做标准化：给 abs / em / log10(eps) 各自拟合 StandardScaler 不同物理量纲被分开处理，避免某一列的统计量影响另外两列
eps 处理 原空间训练/评估 log10(eps) 在训练/评估全链路一致；评估后 10** 还原 eps 量级跨度大、重尾，log 空间更稳定，三任务的梯度可比

二、分子表征（特征）

项目 原始版 改进版 为什么
预训练编码器 TrfmSeq2seq 同样使用 保持 backbone 能力不变
向量聚合 4×H 拼接：mean / max / first-token / penultimate-first 复现同样的 4×H 聚合（封装成 OriginalStyleEncoder） 向后兼容原工程的特征口径，避免“特征变了带来指标波动”

三、模型结构

项目 原始版 改进版 为什么
回归头 两层 MLP → 3 维输出（abs, em, eps） 两层 MLP → 3 维输出（abs, em, log10(eps)） 与“标签逐列、eps 取 log10”的设计一致
额外分支 无 新增“存在性判别头（presence gate）”：输出 2 个 logit（em 是否应有值、eps 是否应有值） 你的数据存在缺失标签且有“缺失时最好别给值/给极小值”的业务语义；存在性分支让模型学会“该列是否该出现”

四、损失与训练策略

项目 原始版 改进版 为什么
多任务权重 等权 MSE（三列一起算） 带权 MSE + 缺失掩码：权重 abs:em:eps = 5:2:1；缺失列不计入该列损失；在标准化/对数空间计算 贴合你的业务优先级（最大吸收波长 >> 最大发射波长 >> 消光系数），同时避免缺失样本“误导”优化
训练日程 单阶段从头到尾一起训 两/三阶段课程学习：先只训 abs → 再开 abs+em → 最后加上 eps 让模型先把“结构整体”学牢（abs），再补“边缘细节”（em），最后学最不稳定的 eps
存在性损失 无 BCEWithLogits 监督 em/eps 的“是否存在” 与 presence 头配套，学习“有/无”的二元信息
编码器是否微调 默认加载并使用 开关可配（默认冻住；需要时解冻） 小样本下先稳住 backbone，需要时再细调

五、评估与推理（包含后处理）

项目 原始版 改进版 为什么
数据切分 单次随机切分（8/2） K 折交叉验证（可配 N_FOLDS=5） 结果更稳健，避免一次切分偶然性
标准化对齐 训练时拟合一个 scaler；评估时有“固定路径读取”的做法 每折保存 scaler_fold{k}.pkl（三列各自的 scaler 列表），评估/推理严格用本折的 scaler 反标准化；先每折 inverse，再在原空间集成 防止统计量错配；先 inverse 再集成能避免“被某个 scaler 均值所牵引”
常数解检测 无 在标准化空间打印 mean/std（可选开关） 训练或评估时快速定位“常数输出”坍塌
缺失值后处理 无 presence 门控：sigmoid(presence) 低于阈值 → em 置空（或极小）、eps 置极小；否则用回归输出（eps 先逆标再 10**） 把“缺失”这一业务规则显式体现在输出层，与训练的存在性学习闭环

六、工程与可复现性

项目 原始版 改进版 为什么
日志/指标 训练/验证 MSE、RMSE 训练阶段分开统计回归损失 & 存在性损失；评估输出 RMSE / MAE / R²（三列）与 K 折汇总 更接近业务口径，便于对比
学习率/稳定性 常规 Adam AdamW、可选 ReduceLROnPlateau、梯度裁剪、固定随机种子 小样本回归更稳定
保存物件 best_regressor.pth、一个 scaler.pkl 每折 best_regressor_fold{k}.pth 与 scaler_fold{k}.pkl，以及最终预测 CSV 检查点与 scaler 一一对应；便于复现与排查

一段“把改动串起来”的故事线

  1. 先把量纲问题解决：eps 进 log10 空间，三列逐列标准化。
  2. 把业务优先级写进优化：损失 5:2:1 加权，并且课程学习让网络先把 abs 学好。
  3. 把“缺失=尽量不输出”的语义落到模型里：增加 presence gate，训练端用 BCE 学“有/无”，推理端用 gate 抑制 em/eps 的输出（置空或极小）。
  4. 把评估/推理做严：每折都有各自的 scaler；先 inverse 再集成；验证/测试用 NoOpTransform 保证确定性；加一个常数解自检，定位训练是否坍塌。
  5. 把结果变稳：改用 K 折 汇总指标；保存每折模型与 scaler，方便复现实验与对比。

一句话版总结

  • 原始版：最小可用的“三输出回归 + 单 scaler + 单次切分”的 baseline。
  • 改进版 v3：围绕量纲统一（log-eps / 列级标准化）、任务优先级（5:2:1 + 课程学习）、缺失语义（presence gate + 输出门控）、评估对齐（折内 scaler / 先 inverse 再集成）、**稳定训练（K 折 / 常数解检测 / 复现设置）**做了系统升级，把工程做“稳”，也把业务规则“写进了模型”。
