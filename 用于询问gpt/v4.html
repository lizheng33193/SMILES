你日志里“93 个 NaN”的真正含义

  • 你这折验证集大小是 31。打印“❌ 评估中发现 93 个NaN预测值”，就是 31×3。

  • 这通常来自评估阶段的“整行掩码”：你可能写了类似

    valid = np.isfinite(labels).all(axis=1) → 只保留在 3 维都不 NaN 的行 然后把其它行的 3 维预测都设为 NaN —— 于是统计出来正好是“样本数×3”。

  • 接着你逐维计算 RMSE：

    • abs 维因为每行都不缺，所以还能算（你日志里的 755）
    • em/eps_log 维因为这次验证折没留下可用样本（或被“整行掩码”误排光），于是 RMSE/R² → NaN

换句话说：不是上游 encoder 出 NaN，是目标缺失 + 掩码逻辑把可用样本“误杀”了。

要怎么改，才能在“多任务 + 缺失标签”下稳定训练/评估？

A) 训练阶段（损失）

必须改成“逐维掩码损失”，而不是把整行当成全有标签：

  1. 生成三个布尔掩码：

    • m_abs = isfinite(lam_abs)
    • m_em = isfinite(lam_em)
    • m_eps = isfinite(eps_log)

  2. 把标签标准化（z-score）时，也要逐维只对非缺失的样本用 scaler：

    • scaler.fit 时，每一维单独用非缺失的值去 fit（或手写均值/方差）；不要把全列一起塞进去。

  3. 计算 loss：

    • 逐元素损失 ℓ = SmoothL1(pred_std, label_std)（形状 B×3）
    • 用掩码加权：ℓ = ℓ * [m_abs, m_em, m_eps]
    • 归一化用有效样本的个数：loss = ℓ.sum() / (m_abs.sum()+m_em.sum()+m_eps.sum())（或者按维度分别平均后再均值）
    • 这样有标签的维度才贡献梯度；缺失的维度不参与，不会把 loss 搞成 NaN。

这一步能直接修复“第一轮就 Loss=NaN”的问题。

B) 评估阶段（指标）

逐维评估、逐维掩码，不要“整行掩码”：

  1. 先得到 pred_std → inverse_transform（逐维、只用前面 fit 的 scaler 参数）→ 得到 pred_abs / pred_em / pred_eps_log；

  2. 对每一维 i∈{abs, em, eps_log}：

    • mask_i = isfinite(label_i)
    • 只对 mask_i 为 True 的样本，计算该维的 RMSE/MAE/R²；
    • 若这折 mask_i 全 False（恰好一个样本都没标签），打印 “该维本折无标签，跳过指标”，指标置为 None 或 nan，但不要把其它维指标也置空。

  3. 汇总“均值 RMSE/MAE/R²”时，只对有数值的维度做平均，别因为某一维缺失就整行 NaN。

C) StandardScaler 的拟合

  • 你现在可能是从 train_loader 堆了一个 N×3 的矩阵去 fit，里头包含 NaN；

  • scikit 的 StandardScaler 不支持 NaN，很容易把均值/方差弄成 NaN；

  • 改法：

    • 每一维单独取非缺失的向量 y_i[mask_i] → scaler_i.fit(y_i[mask_i])；
    • 最终把三个 scaler 的 mean_、scale_ 汇成一个 3 维向量存起来（或自己实现 z = (y-mean)/scale 也可以）。

D) K 折切分

  • 现在是普通 K 折，没有“按标签可用性”平衡，所以某一折完全没 eps_log 是有可能的；

  • 如果你希望每一折都覆盖三维标签，用“分箱后的分层 K 折”：

    • 对 em 和 eps_log 分别做“是否缺失”的 0/1 标记；
    • 以这两个标记（以及 abs 的分位箱）拼成“分层标签”，用 StratifiedKFold 尽可能均衡各折中“缺失/非缺失”的比例。

  • 这是锦上添花；只要 A/B 改好了，K 折没有分层也不至于 NaN。

E) 指标打印与告警语句

  • 你现在的“❌ 评估中发现 93 个NaN预测值 - 上游mask问题未解决!”是误导（其实是掩码逻辑把全体样本清空了）；

  • 建议把这句改成：

    • “该折某些维度全部无标签，已跳过该维指标（不会影响其他维）”；
    • 同时打印每维 有效样本数，例如：n_abs=31, n_em=0, n_eps=0，一眼看出是哪维没数据。

还有两个与数据相关但不致命的点（提早注意）

  1. 序列最大长度 你这批 processed_smiles 的 token 数最大=271。请确认预训练 TrfmSeq2seq 的位置编码/最大长度是否 ≥271（很多工程默认 220）。如果小于 271，请在 Dataset 侧统一截断到 max_len，并在 ImprovedEncoder 的池化时只对有效 token 池化（你已经做了），否则会出现位置编码越界或无效位置编码（通常报错，不会变 NaN，但会影响效果）。

  2. 词表规模 你打印“词汇表: 45”。如果这是完整词表，SMILES 的 token 会有不少落到 <unk>；这不会导致 NaN，但会影响拟合上限。后续可以考虑：

    • 降低 min_freq 让词表更充实，或
    • 用 BPE/Unigram 分词法替代手工 token。

一页改造 Checklist（按这个改，NaN 就会消失）
